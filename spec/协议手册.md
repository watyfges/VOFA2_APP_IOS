# 协议手册 v1

本文是手机端与服务端之间的完整线上格式。实现时按本文即可，不需要看 PC 端源码。

- 控制通道：WebSocket（RFC 6455），**每条消息是一个文本帧，帧内是一个 JSON 对象**。
- 字符集：UTF-8，JSON 用紧凑格式，不含换行。
- 单条消息上限 **64 KiB**，超过服务端直接断开（1009）。
- 时间单位：毫秒；数值均为 IEEE-754 double；控件/动作 `id` 是整数，小于 2^53。
- 没有子协议、没有自定义 Header、没有鉴权头；访问码走 `hello` 消息。

---

## 1. 服务发现（UDP，端口 47901）

手机向广播地址的 **47901** 端口发一个探测包，服务端单播回复。

请求（≤ 512 字节）：

```json
{"t":"discover","proto":1}
```

回复（每个服务端一条）：

```json
{"t":"offer","proto":1,"name":"调试台","port":47900,"pin":false,
 "version":"0.1.0","ips":["192.168.1.23"]}
```

| 字段 | 说明 |
| --- | --- |
| `name` | PC 端设置的「本机名称」，给用户选服务端用 |
| `port` | 控制通道端口，**以这个为准**，不要假定 47900 |
| `pin` | `true` 表示该服务端要求访问码，连接时 `hello.pin` 必填 |
| `ips` | 服务端认为自己可达的 IPv4 列表；**优先用回复的来源 IP**，失败再试 `ips` 里的 |
| `proto` | 协议版本，当前固定 1 |

实现要点：

- 广播地址先发 `255.255.255.255`，再发一次本网段定向广播（如 `192.168.1.255`）。
- 探测间隔 ≥ 300 ms，扫 3 次即可；服务端对探测回复全局限速约 200 条/秒，不要高频刷。
- 同一个 `(来源IP, port)` 在 2 秒内去重后展示成一条。
- 手机和服务端必须同一网段；跨网段（不同 VLAN、开了 AP 隔离的 Wi-Fi）收不到回复，
  此时退化为手动输入 `ws://IP:端口`。
- Windows 端默认开启了「专用网络」防火墙规则；公共网络配置下会被拦。

## 2. 连接与握手

连上 TCP 后按标准 WebSocket 握手，URL 用 `ws://<ip>:<port>/`（路径随意，服务端不校验）。

握手成功后 5 秒内必须发 `hello`，否则服务端断开（1001）。

### 2.1 客户端 → 服务端

```json
{"t":"hello","proto":1,"clientId":"pixel-8f2a","name":"Pixel 7","pin":"1234"}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `t` | 是 | `"hello"` |
| `proto` | 建议 | 协议版本，当前 1 |
| `clientId` | 否 | 设备稳定标识（≤64 字符），仅用于展示/去重 |
| `name` | 否 | 手机显示名（≤64 字符），空则由服务端生成「手机 N」 |
| `pin` | 视情况 | 服务端 `pin=true` 时必填，错误会被断开（4003） |

### 2.2 服务端 → 客户端

```json
{"t":"welcome","proto":1,"session":3,"name":"调试台","version":"0.1.0",
 "pin":false,"maxClients":16}
```

`session` 是本连接在服务端的编号。随后服务端立刻推送一条全量 `state`（见 3.1）。

## 3. 服务端 → 客户端消息

### 3.1 `state`：全量快照

收到就把本地模型**整体替换**，不要做差分合并。

```json
{"t":"state","proto":1,"seq":12,"server":"调试台","version":"0.1.0",
 "groups":["默认","底盘","底盘/PID"],
 "pcGroup":"默认",
 "controls":[
   {"id":1000,"label":"kp","group":"默认","v":1.5,"min":0,"max":10,"step":0.01,
    "inc":true,"order":1}
 ],
 "actions":[
   {"id":3,"label":"启动","group":"默认","kind":0,"on":false},
   {"id":4,"label":"闭环","group":"默认","kind":1,"on":true}
 ],
 "conn":{"connected":true,"state":"已连接"},
 "link":{"kind":0,"connected":true,"state":"已连接","ports":["COM3","COM4"],
         "serialPort":"COM3","baud":115200,
         "tcpHost":"127.0.0.1","tcpClientPort":1346,"tcpServerPort":1347,"tcpClients":1,
         "udpHost":"127.0.0.1","udpRemotePort":1346,"udpLocalPort":1347},
 "oneclick":{"sending":false,"sent":0,"total":0,"status":"","interval":100}}
```

| 字段 | 说明 |
| --- | --- |
| `seq` | 单调递增。发现跳号（丢消息）就发一次 `{"t":"sync"}` 重新拉快照 |
| `groups` | 全部命令组，路径形如 `底盘/PID`；客户端自行按 `/` 做层级 |
| `pcGroup` | PC 当前正在看的组，仅用于提示，不影响手机 |
| `controls` | 全部滑块（所有组，不只是当前组） |
| `controls[].inc` | 是否勾选参与一键发送 |
| `controls[].order` | 组内显示顺序 |
| `actions` | 全部按钮/开关。`kind`: 0=按钮，1=开关 |
| `conn` | PC 的串口/TCP 连接状态，只读，用来提示板子是否在线 |
| `link` | 连接面板详情：`kind`（0 串口 / 1 TCP 客户端 / 2 TCP 服务端 / 3 UDP / 4 演示）、`connected`、`state` 文案、`ports` 可用串口、当前串口与波特率、TCP 主机/端口/客户端数 |
| `oneclick` | 一键发送当前状态 |

### 3.2 `value`：数值变化（增量）

```json
{"t":"value","id":1000,"v":1.5,"from":"pc"}
```

- PC 拖动/输入、其他手机写入、服务端限幅后的结果都会广播，**包括发起者自己**。
- `v` 是服务端**实际生效**的值（已经过 min/max 限制），客户端应以它为准。
- `from`：`"pc"` 或 `"c<session>"`，可用来提示「正在被另一台手机拖动」。
- 频率上限约 30 次/秒/控件（服务端合并），不要期待每帧都收到。

### 3.3 `action`：按钮/开关事件

```json
{"t":"action","id":3,"kind":1,"on":true,"from":"c3"}
{"t":"action","id":5,"kind":0,"on":false,"from":"pc","flash":true}
```

- `kind=1`（开关）时 `on` 是新状态。
- `kind=0`（按钮）时 `flash:true` 表示「有人按了一下」，没有持久状态，客户端做一次点击动效即可。

### 3.4 `oneclick`：一键发送进度

```json
{"t":"oneclick","phase":"step","sent":2,"total":5,"status":"已发送 2/5: kp"}
```

`phase` 取值：`start`（开始）、`step`（每一步）、`done`（完成）、`cancel`（被取消，
或中途发送失败/连接断开）、`idle`（没东西可发）。客户端收到 `done` / `cancel` / `idle`
后即可解除「一键发送」按钮的禁用。

### 3.5 `link`：连接状态变化（增量）

```json
{"t":"link","kind":0,"connected":true,"state":"已连接","ports":["COM3"],
 "serialPort":"COM3","baud":115200,"tcpHost":"127.0.0.1",
 "tcpClientPort":1346,"tcpServerPort":1347,"tcpClients":0,
 "udpHost":"127.0.0.1","udpRemotePort":1346,"udpLocalPort":1347}
```

字段与 `state.link` 完全一致。PC 连接建立/断开、切换传输方式、刷新串口列表时都会推一条，
比 `state` 更及时（`state` 是防抖广播）。客户端收到后直接替换本地的 link 状态即可。

### 3.6 `conn`：PC 传输连接状态

```json
{"t":"conn","connected":true,"state":"已连接"}
```

### 3.7 `clients`：在线数量

```json
{"t":"clients","count":2}
```

### 3.8 `error`

```json
{"t":"error","code":"unknown_control","message":"控件不存在或已被删除"}
```

错误**不会**断开连接（`bad_pin` 除外），按 5 节处理。

### 3.9 `pong`

```json
{"t":"pong"}
```

## 4. 客户端 → 服务端消息

除 `hello` 外，其余消息在握手完成后才能发；否则回 `error: hello_required`。

### 4.1 数值：拖动与提交

拖动中（高频、可丢）：

```json
{"t":"value","id":1000,"v":1.234}
```

松手 / 输入完成（必发一次）：

```json
{"t":"commit","id":1000,"v":1.234}
```

数值输入框提交（允许超出 min/max，与 PC 数值框一致）：

```json
{"t":"commit","id":1000,"v":999,"exact":true}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 控件 id，必须来自 `state.controls` |
| `v` | 目标值；`value` 会被限制到 `[min,max]`，`commit` 默认同样限制 |
| `exact` | `true` 时不限制范围，用于调试输入框。普通滑块不要用 |

### 4.2 开关 / 按钮

开关要指定目标状态（幂等）：

```json
{"t":"action","id":4,"on":true}
```

按钮：

```json
{"t":"action","id":3,"trigger":true}
```

### 4.3 一键发送

```json
{"t":"oneclick","group":"默认","intervalMs":100}
```

- `group` 为空时用 PC 当前组；建议**总是显式带上**手机当前选中的组。
- `intervalMs` 可选，服务端会限制到 10..5000。
- 只发送该组里 `inc=true` 的滑块，按钮/开关不参与。
- 正在发送时再发会得到 `error: busy`。
- 取消：`{"t":"oneclick.stop"}`。

### 4.4 勾选参与一键发送

```json
{"t":"inc","id":1000,"inc":true}
```

- 对应 PC 命令编辑里的「参与一键发送数据」复选框，也就是 `state.controls[].inc`。
- 与 PC 上勾选完全等价：会写进 PC 的设置文件，并影响之后**所有**的一键发送，不只是这一次。
- 服务端接受后会重发整条 `state`（`inc` 字段变化），所有在线手机都会刷新。
- 控件不存在返回 `error: unknown_control`；`inc` 不是布尔值返回 `error: bad_request`。
- 旧版服务端不认识这条消息，会返回 `error: bad_request`（"未知消息类型"），客户端应退化为
  「只在本次发送中生效」。

### 4.5 控制 PC 连接

```json
{"t":"link","cmd":"open","kind":0,"port":"COM3","baud":115200}
{"t":"link","cmd":"open","kind":1,"host":"127.0.0.1","port":1346,"banner":"plot0"}
{"t":"link","cmd":"open","kind":2,"port":1347}
{"t":"link","cmd":"open","kind":3,"host":"127.0.0.1","remotePort":1346,"localPort":1347}
{"t":"link","cmd":"open","kind":4}
{"t":"link","cmd":"close"}
{"t":"link","cmd":"refresh"}
```

- `kind`：0 串口、1 TCP 客户端、2 TCP 服务端、3 UDP、4 演示。
- `port`：`kind=0` 时是串口名（字符串），`kind=1/2` 时是端口号（数字）。
- 省略的字段沿用 PC 当前设置；`baud` 省略则用 PC 上次的波特率。
- 已连接时再 `open` 返回 `error: link_busy`，请先发 `close`。
- `cmd=refresh` 让 PC 重新枚举串口，随后推送 `link`。
- 打开/关闭成功后服务端推一条 `link`（并补一条 `state`），客户端以它为准；不要自己猜结果。

### 4.6 其它

```json
{"t":"sync"}
{"t":"ping"}
```

`sync` 让服务端重发 `state`；`ping` 得到 `pong`。

## 5. 错误码与关闭码

### `error.code`

| code | 含义 | 客户端动作 |
| --- | --- | --- |
| `bad_request` | JSON 或字段不合法 | 修正代码；不要重试同一条 |
| `hello_required` | 还没发 `hello` | 先 `hello` |
| `bad_pin` | 访问码错误 | 提示重新输入；连接随后被关闭（4003） |
| `unknown_control` | 控件/开关不存在（PC 上被删了） | 发 `sync` 刷新列表 |
| `bad_value` | 数值非法（非有限数等） | 回退到上一个有效值 |
| `unknown_group` | 组名不存在 | `sync` 后重选组 |
| `busy` | 一键发送正在进行 | 等待 `oneclick.phase=done/cancel` |
| `empty_plan` | 该组没有可发送的滑块 | 提示用户 |
| `not_connected` | PC 端还没连接设备（或服务端还没有客户端） | 提示先连接；`oneclick` 会同时收到 `phase=idle`，解除按钮禁用 |
| `link_busy` | 已经连接，不能直接切换 | 先发 `{"t":"link","cmd":"close"}` |
| `no_port` | 没有可用的串口（PC 上也没选过） | 先 `refresh` 再选端口 |
| `bad_link` | `link.cmd` 或 `kind` 不合法 | 修正参数，不要重试同一条 |

### WebSocket 关闭码

| code | 含义 |
| --- | --- |
| 1001 | 超时（5 秒内没 `hello`，或 45 秒无任何数据） |
| 1002 | 协议错误（帧格式、未加掩码等） |
| 1003 | 只接受文本帧（不要发二进制） |
| 1008 | 触发限流 |
| 1009 | 消息超过 64 KiB |
| 1011 | 服务端发送积压（手机长时间不读数据） |
| 4001 | 被 PC 端「断开」 |
| 4003 | 访问码错误 |

握手时如果服务端已满，会直接返回 HTTP 503（`too many clients` /
`too many connections from this address`），此时 WebSocket 不会建立。

## 6. 限额

| 项 | 值 | 说明 |
| --- | --- | --- |
| 单条消息 | 64 KiB | 超出断开 1009 |
| 同时连接 | 16 台 | 全局 |
| 同一 IP | 4 台 | 同一台设备多开会被拒 |
| 消息速率 | 300 条/秒，突发 160 | 见下 |
| `hello` 超时 | 5 s | 连上不说话会被断开 |
| 心跳 | 服务端每 15 s ping；45 s 无数据断开 | 手机切后台要注意 |
| 发送积压 | 512 KiB | 手机会话卡住不读数据会被断开 |

速率按「令牌桶」计费，每条消息消耗 `1 + 字节数/1024` 点，桶容量 160，每秒补 300 点。
拖动一般 20~30 条/秒，远低于上限；但如果把整个 `state` 反复回发就会很快被限流。

## 7. 同步语义

1. **服务端权威**：唯一真相源在 PC。手机写入只是请求，最终值以广播回来的为准。
2. **快照 + 增量**：连接时一条 `state`；之后 `value`/`action`/`oneclick`/`conn` 是增量；
   增删控件、改组名、改模板会重发整条 `state`。
3. **回声**：自己写入的值也会广播回来（`from` 是自己）。不要因为回声再写一次，否则会形成循环。
4. **冲突**：两台手机同时拖同一滑块，**最后到达的写入生效**，所有人被拉到同一值。
5. **命令组是手机本地视图**：`state` 里带全部组和全部控件，手机自己筛选；
   只有一键发送需要把组名显式发给服务端。
6. **一键发送全局互斥**：同一时刻只有一台设备能触发，其余得到 `busy`。

## 8. 一次完整交互

```
手机                                      PC（服务端）
 |-- UDP 47901 {"t":"discover"} ------------->|
 |<-- {"t":"offer", name, port:47900, ...} ---|
 |-- TCP connect 47900 + WS 握手 ------------>|
 |-- {"t":"hello", clientId, name} ---------->|
 |<-- {"t":"welcome", session:3} -------------|
 |<-- {"t":"state", seq:1, controls:[...]} ---|
 |                                           |
 |-- {"t":"value", id:1000, v:1.2} ---------->|  (拖动中，约 30 次/秒)
 |<-- {"t":"value", id:1000, v:1.2, from:"c3"}|  (回声，已限幅)
 |-- {"t":"commit", id:1000, v:1.5} --------->|  (松手，必发)
 |<-- {"t":"value", id:1000, v:1.5, from:"c3"}|
 |                                           |
 |-- {"t":"action", id:4, on:true} ---------->|
 |<-- {"t":"action", id:4, kind:1, on:true} --|
 |                                           |
 |-- {"t":"oneclick", group:"默认"} --------->|
 |<-- {"t":"oneclick", phase:"start", ...} ---|
 |<-- {"t":"oneclick", phase:"step", sent:1} -|
 |<-- {"t":"oneclick", phase:"done", ...} ----|
```
