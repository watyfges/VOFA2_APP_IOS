# 客户端开发指南

配套文档：[协议手册.md](协议手册.md)（字段、错误码、限额）。

---

## 1. 连接流程

```
启动
 └─ UDP 广播 47901（3 次，间隔 300ms）
     ├─ 收到 offer → 列表展示「名称 · IP:端口」，标记是否需要访问码
     └─ 无回复 → 提供手动输入 ws://IP:端口
 └─ 用户选择 → TCP 连接 → WebSocket 握手
     └─ 5s 内发 hello（服务端 pin=true 时带访问码）
         ├─ welcome → 等 state
         └─ error:bad_pin → 提示重输访问码（连接会被关）
 └─ state 到达 → 渲染界面
```

关键点：

- **不要写死 47900**，控制端口来自 offer 的 `port` 字段（PC 端可以改）。
- 优先用 offer 的**来源 IP** 连接；失败再试 `ips` 数组里的地址。
- `hello` 里的 `clientId` 用设备持久标识，`name` 用机型或用户可改的名字。
- 握手成功后服务端会主动推 `state`，不需要客户端请求；但如果 2 秒没收到，发一次 `{"t":"sync"}`。

## 2. 界面要求

按 PC 右侧「参数/命令栏」的信息结构组织，不要引入 PC 上没有的概念：

| 区域 | 内容 | 数据来源 |
| --- | --- | --- |
| 顶栏 | 服务端名称、连接状态、在线提示 | `welcome.name`、`conn` |
| 命令组 | 下拉/标签页，按 `/` 分层 | `state.groups` |
| 开关/按钮 | 开关用 Switch，按钮用普通按钮 | `state.actions`（`kind` 区分） |
| 参数滑块 | 标签 + 滑条 + 可编辑数值框 | `state.controls` |
| 一键发送 | 按钮 + 进度（`sent/total`）+ 取消 | `state.oneclick` 与 `oneclick` 增量 |

显示规则：

- 只显示当前选中组里的控件（`group` 精确匹配，组名是完整路径如 `底盘/PID`）。
- 滑块范围/步长直接取 `min/max/step`，数值框允许输入超出范围（提交时带 `exact:true`）。
- `oneclick.interval` 可作为「发送间隔」展示，但通常不需要给手机改。
- `conn.connected=false` 时在顶部提示「PC 未连接板子」，此时操作仍会记录，但数据发不出去。

## 3. 交互规则

### 滑块

| 时机 | 动作 |
| --- | --- |
| 拖动中 | 发 `value`，**限制在 20~30 次/秒**（按 33 ms 节流），可丢帧 |
| 松手 | 必发一次 `commit`（携带最终值） |
| 收到回声 | 以回声值为准更新显示；自己正在拖的那一路不要被回声打断 |
| 数值框回车 | 发 `commit`，带 `exact:true` |

注意：PC 上「拖动时实时发送」关闭时，手机拖动过程中的 `value` **不会**下发到板子，
只有 `commit` 才下发。这是 PC 的既有行为，手机端不需要为此做特殊处理，但调试时要心里有数。

### 开关 / 按钮

- 开关：发 `{"t":"action","id":<id>,"on":<目标状态>}`，是**设置目标值**而不是「翻转」。
  本地先乐观更新，收到 `action` 回声后以回声为准。
- 按钮：发 `{"t":"action","id":<id>,"trigger":true}`。按钮没有状态，
  收到 `flash:true` 的回声时做一次点击动效即可。建议对同一按钮做 300 ms 防抖，避免连点。

### 一键发送

- 点击后禁用按钮，直到收到 `phase` 为 `done` / `cancel` / `idle`，或 `error: busy`。
- 进度条用 `sent / total`，状态文字用 `status`。
- 「取消」发 `{"t":"oneclick.stop"}`。
- 发送的是该组里 `inc=true` 的滑块，按 `order` 顺序；手机不参与排序。

### 多台手机

- `value` / `action` 的 `from` 字段是 `"pc"` 或 `"c<session>"`，可以据此显示
  「PC 正在调整」「另一台手机正在调整」，避免互相抢滑块时困惑。
- 冲突策略是最后写入者获胜，**不要加锁或本地暂存后再覆盖**，直接跟随服务端即可。

## 4. 断线与重连

- 心跳：服务端每 15 s 发一次 WebSocket ping，标准库会自动回 pong，这就算「有数据」。
  如果你的库不回 pong，请自行每 20 s 发一次 `{"t":"ping"}`。
- 45 s 内没有任何入站数据，服务端会断开（1001）。
- 重连建议：1 s → 2 s → 5 s 退避，最多 5 次；重连成功后重新 `hello` 并等新的 `state`
  （`session` 会变，不要复用）。
- 被 4001 断开（PC 上点了「断开」）时不要自动重连，改为提示用户。
- 被 1008 断开是触发了限流，重连前先检查自己的发送频率。

## 5. 平台注意事项

**Android**

- 需要 `INTERNET` 权限；局域网广播一般无需额外权限，但部分机型锁屏后会丢广播、断长连接，
  建议前台服务 + 请求「忽略电池优化」。
- 明文连接：Android 9+ 的 `usesCleartextTraffic` / network security config 可能拦截 `ws://`，
  调试阶段请显式允许（生产环境也只连局域网，不要改成公网）。
- 用 OkHttp / Java-WebSocket / Ktor 均可；二进制帧不要用，服务端只收文本帧。

**iOS**

- iOS 14+ 访问局域网（含 UDP 广播）会弹「本地网络」权限，必须在 Info.plist 配
  `NSLocalNetworkUsageDescription`，否则发现和连接都会静默失败。
- ATS 对 `ws://` 可能拦截，本地调试需要 `NSAllowsLocalNetworking`。

**通用**

- 没有 TLS、没有账号体系，只在局域网使用；不要做公网穿透或中继。
- 一个服务端最多 16 台设备，同一 IP 最多 4 台；测试时不要用同一台手机疯狂重连。

## 6. 联调与排错

PC 端日志：`%LOCALAPPDATA%\VOFA2\logs\vofa2.log`，会打印服务启动、手机连接/断开、
被拒绝的原因（连接数上限、同址上限）。

仓库里的 `scripts/remote_ws_probe.py` 是一个零依赖的 Python 参考客户端（握手 + 快照 + 写值），
可以先用它证明 PC 端可达，再排查手机端问题：

```bash
python scripts/remote_ws_probe.py --port 47900
```

| 现象 | 排查 |
| --- | --- |
| 发现不到服务端 | 同一网段？PC 是否点了「启用」？防火墙是否放行专用网络？AP 隔离是否开着？ |
| 能发现，连接被拒 | 端口是否用错（用 offer.port）；PC 是否已到 16 台/同 IP 4 台上限 |
| 握手后无响应 | 是否 5 s 内发了 `hello`；是否发了二进制帧 |
| 收到 4003 | 访问码错误 |
| 一直 `busy` | PC 或另一台手机正在一键发送，等 `phase=done` |
| 拖动没反应但松手有效 | 正常：PC 的「拖动时实时发送」关闭时只有 `commit` 下发 |
| 值改完又跳回去 | 收到的 `value` 回声是权威值（可能被 min/max 限制），以它为准 |

### 自测清单

- [ ] 冷启动能发现并列出服务端，显示名称与 IP
- [ ] 访问码错误时给出提示，不卡死
- [ ] 断开 PC 的远程开关后，手机在 1~2 s 内显示断线并自动重连（PC 重新开启后恢复）
- [ ] 拖动 30 秒不触发限流断开
- [ ] 两台手机同时拖同一滑块，数值最终一致
- [ ] 一键发送能看到进度，能中途取消
- [ ] 切后台 1 分钟再回来，连接仍可用或能自动恢复
